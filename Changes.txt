LiveIcons v1.1 development: 2026-08-01
New. Added CBR cover extraction through the public UnRAR API, including solid archives and IStream input.
Fix. Made CBR cover selection independent of RAR member order using ComicInfo FrontCover metadata, explicit cover names, and natural filename ranking with decode fallback.
New. Added deterministic parser regression tests and recursive corpus smoke testing.
New. Updated zlib to 1.3.2, libmobi to 0.12, and UnRAR to 7.23; retained the required modernized CHMLib fork.
Fix. Removed LiveIcons' copied zlib internals and now use MiniZip's public archive-position API.
Fix. Corrected binary file reading, which previously discarded whitespace and could corrupt files parsed by path.
Fix. Bounded CBR snapshot/decompression work and checked decoded bitmap dimensions before allocation.
Fix. Hardened thumbnail-provider COM entry points against null and uninitialized arguments.
Fix. Restored the required undecorated COM DLL exports in Win32 builds.
Fix. Added no-throw COM/export boundaries, deterministic resource ownership, bounded parser inputs, and exception-to-HRESULT translation.
Fix. Hardened the retained CHMLib fork against cyclic directories, invalid LZX metadata, unchecked arithmetic, allocation failures, and native resource leaks.
Fix. Hardened libmobi against malformed HUFF/CDIC and DRM metadata and checked hybrid-document allocation failure.
Fix. Rejected multi-volume CBR input and RAR dictionaries above 128 MiB before UnRAR processing.
New. Added a privacy-preserving, rate-limited diagnostic log under LocalLow with rotation and stale-file cleanup.
New. Added adversarial IStream, malformed-input, COM lifetime, exception-firewall, and logger boundary tests.

LiveIcons v0.1 alpha: 2022-02-17
New. Added the code from my other project that I devcided to convert to this one and started to implement image management for thumbnails.
New. Added zlib 'develop' branch as a submodule, made it to compile with the following changes:
The zlib repo is added as a submodule and switched to the 'develop' branch because main is several years behind it.
There is 2 projects zlibstat - compressiong and minizip - working with zip files. Had to do the following changes to the zlib projects:
1. Changed 'Platform toolset' for zlibstat and minizip from VS2015(v140) to VS2022(v143). Also had to remove Itanium platform support because VS2022 does not have a toolset for it.
2. Changed the C/C++ language to the latest.
3. Removed inffas8664.c from the zlibstat project, it looks like its functionality moved, but the vcproj did not get updated by the author.
4. Disabled warnings C5105 and C4244 for zlibstat, that makes the compilation output cleaner.
5. Changed the reference for minizip from the dynamic library to the static zlibstat. Modified linker settings to link with the static library for all targets.
6. Removed 'ReleaseWithoutAsm' from zlibstat configuration, made the regular Release config to be without using asm, this is because the asm files is missing in the 'develop' branch.
7. In minizip disabled warning C5105, C4267 and C4067.
8. In minizip removed the compilation option /Gm from the Debug build as this option is deprecated.
9. Changed minizip project type to 'Static library'.
10. Included ioapi.* and iowin32.* files into minizip project, for some reasonty it was missing it in 'develop' branch.
